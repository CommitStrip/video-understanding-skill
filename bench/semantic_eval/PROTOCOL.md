# 语义级评估协议（Semantic Evaluation Protocol）

> W3（2026-09-02）引入。动机：`bench/` 既有对比用**像素差分覆盖率**做准确性指标，
> 而本 Skill 的选帧算法本身就用像素差分——**评估尺子与被评方法同构，天然偏向自己**。
> 典型误判：一个纯色画面只要亮度/色相在抖动，像素尺子就判定"每秒都有内容变化"，
> 而语义上一帧都不用多选。本协议把评估升到**语义场景层**，打破这层同构偏差。

## 1. 标注单元：语义场景段

把视频时间轴按**语义内容**（而非画面运动）切分为连续、不重叠的场景段：

```json
{
  "video": "example.mp4",
  "duration_s": 48.0,
  "source": "human | vlm-assisted",
  "scenes": [
    {"start_s": 0.0,  "end_s": 12.0, "desc": "纯蓝色空镜（亮度缓慢抖动，语义单一）"},
    {"start_s": 12.0, "end_s": 24.0, "desc": "主持人近景讲解"},
    {"start_s": 24.0, "end_s": 36.0, "desc": "数据中心机房纹路面板"},
    {"start_s": 36.0, "end_s": 48.0, "desc": "回到纯蓝色空镜（与第一段同语义）"}
  ]
}
```

切分判据（给标注者）：
- **场景切换**：说话人/机位/地点/主题/画面功能（空镜 vs 讲解 vs 字幕板）发生变化；
- **不切换**：同场景内的镜头运动、光照抖动、字幕滚动、纯色底色明暗变化；
- 边界精度 ±0.5s 可接受（指标按时长加权，边界误差影响被摊薄）；
- `desc` 用一句话，供后续人读和 VLM 校对。

## 2. 标注来源（两种）

### 2.1 人工标注
直接编辑 `ground_truth.json`（schema 如上）。适合短视频（<5 分钟）或已有分镜表/章节表
（直接映射成场景段）的素材。

### 2.2 VLM 辅助标注（半自动，`annotate_vlm.py`）
1. 运行 `python bench/semantic_eval/annotate_vlm.py --reps ... --keyframes ... --aligned ...`
   ——脚本把**代表帧 + 对齐字幕**整理成待标注清单；
2. 缺省模式：只生成 `vlm_prompt.md`（给多模态 VLM 的 prompt 模板）与
   `annotation_manifest.json`（帧清单 + 逐帧附近字幕），人工粘贴给任意多模态模型；
3. 设置 `VLM_API_BASE` / `VLM_API_KEY`（/ `VLM_MODEL`）环境变量后重跑：
   自动调用 OpenAI 兼容 API，把代表帧缩略图与字幕喂给模型，产出场景表**草稿**；
4. **人工校对必选**：VLM 输出只作草稿，边界与 desc 必须过目修正后再定稿
   （把 `source` 字段改为 `human` 表示已校对）。

## 3. 指标定义（`eval_semantic.py`）

记 GT 场景段集合 `S = {(s_i, e_i)}`，时长 `d_i = e_i - s_i`，总时长 `D = Σ d_i`；
代表帧集合 `R = {t_j}`。帧 `t_j` 落入场景 `i` 当且仅当 `s_i <= t_j < e_i`。

### 3.1 语义覆盖率（主指标）
```
coverage = Σ_{i: R 落入场景 i 的帧数 >= 1} d_i  /  D
```
按时长加权：长场景漏选比短场景漏选扣得多。1.0 = 每个语义场景都至少有 1 张
代表帧可供 LLM 理解；这是"语义无遗漏"的硬下限。

### 3.2 冗余度
```
redundancy = |R| / |S|
```
越接近 1 越精简（每场景恰好 1 帧）。k>1 的选帧策略预期 >1；
>1.5 且覆盖率已 1.0 时，提示可加大 interval 或开去重。

### 3.3 场景保真（可选）
```
gini = Gini({ n_i : 场景 i 中的代表帧数 })
```
基尼系数衡量代表帧在各场景分布的不均匀度（0=完全均匀，1=全部堆在一个场景）。
覆盖率打满时该值越低越好；用于诊断"帧堆在高频切换段、长静段被掏空"的偏斜。

### 3.4 指标局限（自我声明）
- 语义覆盖率同样依赖 GT 质量；VLM 辅助标注未校对前只算草稿指标；
- 冗余度对"场景数"敏感：同一素材粗/细粒度两套 GT 会给出不同冗余度，
  对比实验必须用**同一套 GT**；
- 三个指标都不度量"选的时间点是否是场景内的代表瞬间"（如高潮帧），
  该维度仍需人工抽查或后续 VLM 打分补充。

## 4. 与旧像素指标的对比

旧协议（`bench/land_compare.py`）：1s 桶、桶首尾像素差分 >3% 记为"有变化秒"，
覆盖率 = 被选帧覆盖的有变化秒占比。**它的"真值"本身就是像素差分**，与本 Skill
选帧算法同构；对"语义静态、像素抖动"的内容（纯色屏、噪点、镜头热扰）会伪造
大量"变化秒"，对"语义已切换、画面相似"的内容（同机位换话题）则完全失明。
合成对照实验见 `gen_synthetic_gt.py`（纯色 A→纯色 B→纹路 C→纯色 A'）。
